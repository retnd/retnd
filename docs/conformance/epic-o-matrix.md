# EPIC O conformance matrix

Specification: `docs/EPIC-O-observability-integrations.md` (FR-45 through FR-50).
Tracker: #898. Sub-issues: O1.1 #899, O1.2 #900, O1.3 #901, O1.4 #902, O1.5 #903. This file lands under #897.

One row per exit-gate line of `docs/EPIC-O-observability-integrations.md` §5 and per planted violation of §4. Every row carries a **falsification**: the mutation that must turn that cell red. A row is `PASS` only once that mutation has been run and watched to fail, which is the distinction this file exists to hold onto — a check that passes on the tree it ships with has proven nothing (`docs/epic-checklist.md` §12).

## Why this file exists in this shape

EPIC O adds three surfaces an operator points third-party software at: an HTTP endpoint a scraper polls every fifteen seconds, a log stream shipped to somebody else's store, and an outbound HTTP request to an address an operator typed. Every one of them is a place a secret can leave this process, and two of them are places a *silence* reads exactly like health:

- a Grafana panel querying a metric name this product never emitted draws a flat, empty, reassuring line;
- an Alertmanager alert pushed once expires after `resolve_timeout` and reports itself resolved while the backup is still stale.

Neither failure raises anything. Both are caught here or not at all, so both have a row whose falsification is a *planted* version of exactly that silence, not a re-reading of the code.

The third reason is narrower and it is the one the panel found first: this product has no credential a scraper can present (the sole credential on `origin/main` is an interactively-minted `backupd_session` cookie), so "the endpoint is behind auth" is a claim that can only be settled by an unauthenticated request being refused. Row 1 is that request.

## How to read an outcome

| Outcome | Means |
| --- | --- |
| `PASS` | The check exists, runs in `scripts/ci-local.sh`, and has been shown to go red against a real planted violation. The falsification column names the mutation and it is automated in `scripts/observability/selftest.sh`. |
| `PARTIAL` | Part of the claim is checked and shown to fire, and the rest is not: either it waits on an unlanded issue, or it cannot be run here at all. The row says which half is which and which of those two it is. |
| `BLOCKED` | The check is specified here and cannot conclude today, because the code it certifies is not merged. Not a pass, and not a fail. The row names the issue. |
| `BY HAND` | There is no automated check and there will not be one, because the question is about a person reading a screen. The row says who checked, against what, and when. Two rows are this, and both say so in the certifies column rather than borrowing a green from a neighbouring check. |

Every row below is `BLOCKED` today. This file lands with the specification, before any implementation, which is the only state in which "no row is green because nobody looked" is verifiable by inspection.

## Rows this epic deliberately does not have

Naming them is part of the matrix: a reader should be able to tell an absent row from an overlooked one.

- **No metric-rename row.** EPIC R owns the naming surface (FR-36–FR-44). EPIC O emits no new family name and renames none, so a row here would either duplicate EPIC R's or contradict it.
- **No capability-contract row.** Serving a route the router already hosts is not new platform behaviour, so `apps/common/platform/capabilities/` is untouched. The cross-provider conformance suite still runs, under O-15.
- **No trace or span row.** There is no span model in this product and this epic does not invent one (§6).
- **No store-submission row.** No listed screen changes: the new controls are a section on a Settings page no store listing depicts. O-24 records that judgement; had a listed screen changed, `docs/conformance/submission-preflight.md` would have a row going back to outstanding.
- **No per-set-override row.** Nothing EPIC O adds is a property of a backup set, and the spec's FR-49 records the decision per knob. A conformance row asserting the absence of a field would certify a choice, not a behaviour.
