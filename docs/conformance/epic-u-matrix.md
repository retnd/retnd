# EPIC U conformance matrix: an MCP server for agents

This is the list of claims EPIC U makes, each tied to the test that will go red if the claim stops being true, plus the **mutation that has to be run and watched to fail** before the row may say `PASS`. `BLOCKED` is for a claim whose proof has not landed on `main`, citing the epic (#1343, which stays open until the release) with the sub-issue that unblocks it in the last column.

**Every row is `BLOCKED` on the day this file lands, and that is the point.** Nothing of this epic exists in the tree yet. Where a row names a test, it is an existing test or file the proof will extend or stand beside, never one I made up; the guard that reads this file resolves every backticked path a `PASS` row cites, so a row that named a test before it existed would fail the moment it flipped. No row flips until the pull request that lands its proof on `main` has also had its falsification run and watched to fail.

`docs/EPIC-U-mcp-server.md` is the contract. Its phase exit gates are the checkbox lists this file numbers `U1.n` and `U2.n`, in order, one row per line. Its section 3.6 consensus table is `UC-01` to `UC-06`. Its section 6 guard table is the `UV.n` ledger, one row per guard, in order.

## Reading a row

| Column | Means |
|---|---|
| ID | `U1.n` and `U2.n` for exit-gate lines, `UC-nn` for the review findings, `UV.n` for the planted-violation ledger |
| Claim | What is asserted, in the epic's words |
| Executable proof | What exists today that the proof will extend, as a path or `<package dir>:<TestName>`. The row says in words what the new proof has to be |
| Falsification | The mutation that must turn the proof red. Once run, the row gains the date and what caught it |
| Status | `BLOCKED (#1343)` now. `PASS` only once the falsification has been run and watched to fail, with the date. `PARTIAL` when a half cannot be shown, saying what is missing. `BY HAND` for a check nobody can automate, naming who checked what and when |
| Waits on | The sub-issue, and the pull request once one is open |

## The guards that read this file

`core/tests/compat/matrix_test.go` gains this pair in its table in #1345's first commit, red, because the scaffold pull request that lands these two documents is documentation only. From then on its five tests hold this file to the spec on every gate run: one row per exit-gate line in each phase, contiguous (`TestTheMatrixHasARowPerGateLine`); one `UV.n` row per guard in the spec's section 6 table (`TestTheViolationLedgerIsHeldToTheSpecsGuardTable`); every path a `PASS` row cites resolves (`TestTheMatrixDoesNotCiteSuitesThatDoNotExist`); a spec box is ticked exactly when its row is `PASS` (`TestTheSpecsExitGateBoxesAgreeWithTheMatrix`); and every `BLOCKED` row cites an issue GitHub says is open (`TestEveryBlockedRowCitesAnIssueThatIsStillOpen`).

## The limits of this matrix

It does not prove a model will not be persuaded by what it reads, and it cannot: it proves the persuasion cannot act without a person reading the command. It does not prove the transport is confidential: it proves the HTTP transport is off until an operator turns it on. It proves equal answers across the clients retnd-tests drives, not across every MCP client an operator might connect. A row that says more than that is wrong.
