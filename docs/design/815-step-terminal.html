Every script step gets its own terminal, and it is a log view that refuses to be a terminal

Issue #815, 2026-09-13. One component, ui/shared/src/components/StepLogTerminal.tsx, slotted into the selected step of L7's run timeline. Props are one step, two ids and one method: workflowStepLogs(runId, stepId, {after, wait}). The bytes it draws are a hook script's stdout on a source host — the least trusted machine in the deployment — so the design question is not "which emulator" but "how little of an emulator can this be and still be readable".

The header is the five facts a reader needs before they believe a line of the log: which script, which phase and scope, where it ran, how it ended, and the hash of the bytes that ran. Local is never called an engine container. A local hook runs under the host workflow runner on the NAS itself, and telling an operator otherwise sends them looking for their script's side effects in the wrong filesystem. The SHA is an em dash whenever the runs API does not carry one (L6's WireWorkflowStep has no hash field) rather than joined from somewhere else: invented provenance is worse than none.

Nothing is removed silently. The footer's tally is aggregated rather than inline because a hook that colours one word per line would otherwise produce a log that is half markers; what an operator actually needs is "was anything taken out, and was it the kind of thing a backup script has any business writing". A title sequence in a report hook's output is the second one. The truncation marker is in position, not at the end: a bound reached mid-hook is a fact about a place in the log, and it is drawn in this product's words and never the script's, so no hook can forge one.

3 · the read failed, and the cursor is the reason nothing is lost

Live delivery was dropped 1 time and replayed from the durable log at the last line drawn, so nothing here is missing or repeated.
read after = read→ queue (bounded, 2 000)→ take = render = acknowledge   backlog over the bound, or a reconnect → drop the queue, read := acknowledged
Two numbers and one rule. acknowledged is the highest sequence that reached the screen; read is where the next page starts. Before every read, if the queue is already full, it is thrown away and read collapses onto acknowledged — so a throttled consumer, a paused follow and a browser reconnect are one case, not three. No duplicate is possible (a read starts strictly after a sequence, and nothing at or below acknowledged is ever handed over twice); no gap is possible (the only position a read resumes from is one the consumer confirmed). The check is before the read rather than after, because a check afterwards would discard records the consumer never had a chance to take — a single page larger than the bound would be read and dropped for ever. All of this buffering is in the browser and all of it is bounded: the engine's fan-out is non-blocking and its wait is clamped, so a follower cannot add a millisecond to a script's wall-clock duration.

"This step has not run yet" / "This step was skipped, so it wrote nothing" / "Reading this step's log…" / "This step wrote nothing to stdout or stderr." Four different facts, four sentences. A single "no output" would misreport three of them — and the one that matters most is the difference between a hook that ran silently and a hook that never ran.
Decision 1 — there is no terminal emulator, and that is how the library requirement is met. #815 asks for a pinned production release of the terminal library and no runtime-loaded third-party terminal code, with disableStdin, no WebLinks addon, no title integration and window manipulation off. Satisfied here in the strongest available way: there is no third-party terminal code at all. This product already renders its run-level log with its own React view (components/ActivityDock.tsx), and the emulator features that view lacks are exactly the ones this issue requires be switched off. Importing an emulator in order to configure them away would ship a parser for the sequences this surface has decided to refuse, and would be a runtime dependency added to defend against itself. The renderer is first party and in tree, which pins it the way nothing else can: it moves when this repository moves, it is reviewed with it, and there is no version resolution, no CDN and no dynamic import in its path. The suite asserts that as the whole dependency closure — every import in these files is relative, @shared/*, or react — and separately that nothing anywhere in them assigns markup. The cost is stated rather than hidden: no colour, no cursor addressing, no in-place repaint. All three are consequences of refusing to emulate, and all three are reported to the reader.

Decision 2 — the profile is data, published on the element. HARDENED_PROFILE is not configuration — nothing reads it to decide what to do, because a switch that can be turned on is a switch that will be. The log element carries data-stdin="disabled", data-link-activation, data-title-integration, data-window-manipulation, data-device-reports, data-scrollback and data-renderer, derived from that constant, so the claim on screen and the claim in the code cannot drift apart and the suite asserts the rendered value.

Decision 3 — one instance, a hundred logical logs. Every step owns a logical log; the browser owns one viewer. Per-step state (follower, cursor, lines, tally) lives in a ref keyed by step, so changing stepId is a swap inside one instance: no DOM is thrown away, switching back is instant and resumes from the cursor it reached rather than re-reading from zero. The cache is bounded at eight steps, because "quickly switchable" must not mean a hundred scrollbacks held at once; an evicted step costs one durable re-read and nothing else. The suite rerenders a hundred steps and asserts the same DOM node throughout, and that the step left behind stops being read.

Decision 4 — the download is the sanitised content. The durable log is already redacted by the engine, so no secret is in it; what the file adds is the same escape filtering the screen applies, plus the header facts, the capture-order caveat and a line naming what was removed. A download that handed back raw bytes would re-arm every sequence this component disarms — in a file an operator opens in a terminal, which is the one place OSC 8 and a title sequence still work. Copy and download produce the same text, from one function, so the two can never disagree.

Decision 5 — no hover-only copy. Everything this surface owes its reader is visible text: the read-only profile, the capture-order caveat, what the filter removed, what the scrollback dropped, what a reconnect replayed. Each is a load-bearing qualification of what is on screen, and a qualification that only appears on hover is one a reader can miss while drawing exactly the wrong conclusion. That also keeps this component out of the shared tooltip registry, which L7 owns this cycle.
