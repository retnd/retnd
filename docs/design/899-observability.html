2026-11-19. This note is a record of a decision at the moment it was taken, and it is not kept in step with later work. The log level (#900) and the alert delivery (#901) are two read-only lines for now and gain their controls from their own issues, under their own tooltip prefixes.

2. Decisions

The switch is a checkbox that writes at once. It sends PATCH /settings/observability with metrics_enabled, and the card then shows what the engine answered rather than what it hoped it had written. The line under it is the equivalent command, so the terminal always has the same act.

The report cache is a number of seconds with the engine’s floor said before anything is sent. The floor is one second (config.MinMetricsMinRebuildInterval); the engine refuses lower and writes nothing, and the card says the same in the field’s own error slot, in words and not only colour.

The token has one home. It exists in the card’s state for the life of the reveal and nowhere else: not in the status line (which shows the eight-character prefix only), a tooltip, a live region, an error or browser storage. “I have stored it” drops it. The mint is POST /settings/observability/scrape-token so an operator with only a browser can wire Prometheus; over a connection that is not encrypted it asks the same question a password does before the request is sent.

Minting again says what it costs. The old token stops working at once, with no overlap, so the line under the button says so and the reveal repeats it.

The two read-only lines have no tooltip. They are statements of fact and not controls; a field whose effect the code cannot yet state gets no pop-up (checklist section 5).

Nothing is per backup set. A scrape endpoint, a log stream and an alert channel belong to the deployment, so there is no per-set card.
